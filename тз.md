# Техническое задание на разработку веб-приложения для ресторана ATRIUM

## 1. Описание проекта
Разработка полностекового веб-приложения для ресторана, предоставляющего клиентам возможность просмотра меню, регистрации, а также онлайн-бронирования столиков на определенное время с обязательным внесением предоплаты. 

## 2. Архитектура и стек технологий
* **Фронтенд:** React, React Router v7 (для маршрутизации, включая загрузчики и действия), Zustand (для управления глобальным состоянием клиента).
* **Бэкенд:** FastAPI (Python) для реализации REST API.
* **База данных:** PostgreSQL (реляционные данные: пользователи, брони, столы).
* **S3 Хранилище:** MinIO (для хранения медиафайлов: фотографии интерьера, блюд из меню, аватары пользователей).
* **Инфраструктура:** Docker Compose (оркестрация контейнеров: frontend, backend, postgres, minio, nginx в качестве reverse-proxy).
* **Интеграции:** Платежный шлюз (например, Stripe, ЮKassa или Tinkoff) для проведения транзакций по предоплате.

---

## 3. Ролевая модель
1. **Неавторизованный пользователь (Гость):** Может просматривать главную страницу, меню, интерьер ресторана, контакты и наличие свободных столов.
2. **Авторизованный клиент:** Может бронировать столы, оплачивать бронь, просматривать историю своих бронирований, управлять профилем.
3. **Администратор:** Управляет меню (CRUD блюд, загрузка фото в MinIO), рассадкой (CRUD столов), отслеживает и меняет статусы бронирований, просматривает статистику оплат.

---

## 4. Функциональные требования

### 4.1. Модуль аутентификации и профиля
* Регистрация и авторизация (JWT-токены).
* Личный кабинет клиента с историю бронирований и статусами оплат.
* Редактирование личных данных (имя, телефон, email).

### 4.2. Модуль бронирования столиков (Core Feature)
* **Выбор параметров:** Клиент выбирает дату, время, количество гостей.
* **Схема зала:** Выдача доступных столиков в зависимости от выбранного времени. Ограничение на создание пересекающихся броней (защита от овербукинга).
* **Процесс бронирования:**
    1. Клиент выбирает свободный стол.
    2. Система создает бронь со статусом `pending_payment` и удерживает стол на 15 минут (чтобы другие не могли его занять).
    3. Клиент перенаправляется на страницу оплаты.
    4. При успешной оплате webhook от платежной системы меняет статус брони на `confirmed`.
    5. При неоплате в течение 15 минут бронь аннулируется (`cancelled_timeout`).

### 4.3. Каталог меню
* Разделение блюд по категориям (горячее, напитки, десерты).
* Фотографии блюд загружаются администратором через FastAPI бэкенд и сохраняются в MinIO. Бэкенд генерирует presigned URLs для безопасной отдачи изображений на фронтенд (или публичный bucket, в зависимости от настроек приватности).

## 5. Структура базы данных (PostgreSQL)

| Таблица | Описание | Основные поля |
| :--- | :--- | :--- |
| **Users** | Пользователи системы | `id`, `email`, `password_hash`, `phone`, `role`, `created_at` |
| **Tables** | Столики в ресторане | `id`, `number`, `capacity`, `is_active` |
| **Reservations**| Бронирования | `id`, `user_id`, `table_id`, `start_time`, `end_time`, `guests_count`, `status`, `deposit_amount`, `payment_id` |
| **Menu_Categories**| Категории блюд | `id`, `name`, `description` |
| **Menu_Items** | Позиции меню | `id`, `category_id`, `name`, `description`, `price`, `image_key` |

## 6. Основные эндпоинты API (FastAPI)

* **Auth:**
    * `POST /api/v1/auth/register` — регистрация.
    * `POST /api/v1/auth/login` — получение JWT.
* **Menu:**
    * `GET /api/v1/menu` — получение списка категорий и блюд.
    * `POST /api/v1/admin/menu/upload-image` — загрузка фото блюда в MinIO.
* **Tables & Reservations:**
    * `GET /api/v1/tables/availability` — запрос доступных столов на конкретное время.
    * `POST /api/v1/reservations` — создание черновика брони и генерация ссылки на оплату.
    * `GET /api/v1/reservations/me` — история бронирований текущего пользователя.
    * `POST /api/v1/webhooks/payment` — эндпоинт для приема статуса оплаты от эквайринга.

## 7. Инфраструктура и развертывание (Docker Compose)
Проект должен быть завернут в единый `docker-compose.yml`, состоящий из следующих сервисов:
1. **frontend**: Сборка React приложения на базе Nginx.
2. **backend**: Uvicorn сервер для запуска FastAPI приложения.
3. **db**: Официальный образ `postgres:15` с volume для сохранения данных.
4. **minio**: Образ `minio/minio` для S3-совместимого хранилища.
5. **redis** *(опционально)*: Для управления очередями отложенных задач (снятие брони через 15 минут) и кэширования.
